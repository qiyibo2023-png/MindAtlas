# English / Simplified Chinese platform contract

MindAtlas has one clinical state model and one set of clinical engines. Its two
supported presentation locales are `zh-CN` and `en` (legacy indices 0 and 1).
Clinical IDs, option values, scores, differential directions, safety facts and
thresholds never depend on locale. For example, the existing `suicide.intent`
field means the same fact in both languages; it is not renamed on translation.

## Architecture

- `src/i18n/runtime.js`: strict registration, lookup, interpolation and locale
  selection; presentation-only redraw and temporary DOM draft/focus preservation.
- `src/i18n/catalog.js`: centralized paired translations. Existing content uses
  stable `platform.m_*` migration keys; new entries should use descriptive IDs in
  a namespace such as `common`, `references`, or `explanations`.
- `scripts/validate-i18n.cjs`: mandatory pre-build validation. Missing literal keys,
  incomplete pairs, mismatched interpolation variables and inline Chinese outside
  the reviewed safety metadata fail the build. Basic literal-markup checks reject
  untranslated English UI. Dynamic missing keys throw at runtime, never fall back
  silently to English or display a key.
- `tests/i18n.test.cjs`: bilingual answer-to-ID mapping, full structured-result
  equality, safety scenarios, actual application language-button handlers, every
  implemented assessment section and shared topic/evidence views.

Register both locales together, in Chinese/English order:

```js
I18n.register('handoff', [
  ['heading', ['就诊摘要', 'Visit summary']],
  ['answered', ['已回答 {count} 个问题', '{count} questions answered']]
]);
I18n.t('handoff.heading', lang);
I18n.t('handoff.answered', lang, {count: 3});
```

This example describes an API contract; no handoff module or router is implemented.
Future Router, Adaptive Assessment, Differential, Care Navigation, Clinician
Handoff and Evidence work should register namespaces in the same catalog, use the
same runtime and validation, and store clinical IDs rather than translated text.
The runtime does not HTML-escape interpolated values: escape user-supplied text
at the HTML boundary (or use textContent). Do not add raw health data to catalogs.

Legacy clinical data retains paired arrays for compatibility, populated from
the central catalog. UI selectors all delegate to I18n. Clinical explanations
that include counts use `formatPair`, producing both messages at once without
selecting a clinical locale. The reviewed safety rule/resource metadata remains
beside its rules to avoid rewriting validated core files; the UI selects those
pairs through I18n. Safety labels and intervention text are in the central catalog.

## Switching is presentation only

The language handler retains the route, module steps, answers, safety facts,
acknowledgment, urgency, result object identity, topic dialog, disclosures, drafts,
focus and scroll position. Results already calculated are reused during the
language redraw; ordinary answer edits still invalidate/recalculate results.
DOM drafts exist only for the synchronous redraw, not in persistent storage.

Clinical terms have common keys for obsessions, compulsions, anhedonia, functional
impairment and differential diagnosis. Chinese labels may annotate the English
term on first use; English prose uses English. Proper author names, URLs, scale
identifiers (PHQ-9/GAD-7), reference codes, dates and version IDs are invariant.
Reference organization names and review metadata have bilingual presentation.
The language button deliberately names its target language in that language.

## Audit and fixes

The audit covered 382 questions and their options, 38 assessment sections, result
explanations, summaries, evidence, privacy, validation, navigation, shared topics,
safety clarification, urgent help and medical interruption. It centralized 1,215
message pairs and removed English-only decorative headings. It also fixed:

- OCD summaries missing the `clarify` action's label.
- OCD summaries printing internal boolean values instead of translated answers.
- OCD time-burden explanations containing the selected duration only in Chinese.
- Topic dialogs retaining stale-language text and lacking an in-dialog switch.
- Result timestamps/object identity being regenerated by language redraws.

### Bounded extraction correction

Strict equivalent-input tests exposed a concrete synonym gap: “I am thinking
about suicide” was not recognized like its Chinese counterpart. The initial extraction
correction was extended for the exact life-ending-intent, family-image and medical-emergency examples supplied for final hardening. Ten original extraction lines now differ in total. Bounded phrase changes were made to cover that phrase, explicit negation, `anyone/others`
in harm denials, `fear` with intrusive thoughts, and equivalent harming-thought
phrases. Positive intent in a separate clause still overrides intrusive context.
No safety rule, escalation threshold or schema field changed.

`tests/fixtures/extraction-i18n-patch.json` records the exact before/after lines.
The existing core hash test reconstructs the original extraction bytes using
only the documented ordered replacements, then checks the original SHA-256. The other six
core files are checked unchanged. Original baseline hashes are not overwritten.

The distinction between thoughts, intent and planning is discussed in the
[NIMH adult safety assessment guide](https://www.nimh.nih.gov/research/research-conducted-at-nimh/asq-toolkit-materials/adult-outpatient/adult-outpatient-brief-suicide-safety-assessment-guide).
This reference does not validate MindAtlas's regex extractor or its thresholds.

## Verification and clinical limits

```sh
node scripts/test-all.cjs
node scripts/verify-baseline.cjs
```

The test runner rebuilds from source and includes all original 139 checks plus
the bilingual suite. It tests translated labels against the same option IDs and
compares complete structures with a fixed clock. Browser verification additionally
covers real language-button and keyboard actions, draft/answer retention and
390px layouts in both languages.

Functional parity of the tested paths is not independent clinical equivalence
validation. Clinical translation review, validated scale equivalence and broader
language-understanding evaluation remain required. The bounded regex extractor
cannot guarantee equal interpretation of every possible paraphrase. Unknown
input continues through the existing clarification/fail-safe behavior. Do not
describe this platform or its translations as clinically validated on this basis.

No Symptom Router or additional disorder module was added.

## Final hardening additions

Catalogs use entry lists so duplicate keys cannot be overwritten by JavaScript object parsing. The build rejects orphan keys, duplicate entries and unexpected inline/fallback text. A 14-concept glossary is available on the Evidence page via I18n.terms. The dependency-free i18n/fallback.js contains intentionally bilingual recovery copy for cases when translation lookup itself fails; it blocks ordinary assessment navigation without changing clinical state or calling a technical failure a confirmed emergency.

Final browser validation covers 1280px desktop, 768px tablet and 390x844 mobile in both locales: 78 page/state checks plus 24 expanded summary/evidence checks. Tablet English header overflow was fixed by wrapping navigation. All interactive buttons have at least 44px height (safety controls retain 48px), OCD progress has an accessible label, and shared secondary text contrast was improved.

The required exact family-harm example reports unwanted frightening images and denies desire; intent remains unknown until clarified. A desire denial is never silently promoted to an intent denial. Both languages now yield the same structured facts. Free-text entry remains safety-only; OCD checking parity is assessed using the existing structured OCD questions, without adding a symptom router.

## Router v1 extension

The `router` namespace adds 28 paired messages; the catalog now has 1,243 keys. Router clinical IDs, candidate ranking, Safety acknowledgment and pending profiles are independent of locale. Extraction patterns are bilingual lexical data in `router/extraction.js`, explicitly exempt from the inline-Chinese UI check; all Router presentation remains in the catalog. Three exact bilingual profile/result equivalence tests and bidirectional switching tests extend the existing 39-check bilingual suite.

## Differential v1 extension

The Differential namespace adds 125 bilingual pairs (1,368 total). Normalized concept IDs, rule IDs and tri-state values never depend on locale. New tests compare serialized results across languages and preserve all stores/result identity during switching. Fixed clarification controls, summaries and uncertainty explanations use the same central catalog.

## Trauma v1 extension

Trauma adds 153 centralized bilingual pairs (1,521 total), with original adult self-assessment language and no event narrative prompts. All domain states survive language switching. Missing focus IDs now resolve to null before focus restoration, fixing a browser-discovered presentation error during interruption; an automated regression covers it.

## ADHD extension

ADHD question labels, choices, explanations, validation, summaries and safety additions use central `adhdUI`, `adhdEvidence` and `adhdSafety` namespaces. The catalog contains 1674 complete bilingual keys at this checkpoint. Clinical IDs are shared across languages. ADHD tests cover structured and Router parity, uncertainty, safety and in-progress/result language switching; browser fixtures compare all module/Safety/Router/Differential stores before and after each switch.

## Eating bilingual extension

All Eating labels, options, results, medical warnings, validation and summary text use `eatingUI` and `eatingEvidence`. The central completeness validator checks 1869 keys. Stable structured IDs are language independent; automated and browser checks cover all module steps, Safety, Router, Differential and summaries. Translation and clinical-rule review remain required independently of these implementation checks.
